# การค้นความหมายและหลักฐานจาก PDF สองภาษา

ตรวจแหล่งข้อมูลวันที่ 13 ตุลาคม 2569 ข้อเสนอต่อไปนี้แยกระหว่างหลักฐานจากงานวิจัยกับการตัดสินใจของโครงการ

## งานวิจัยและเอกสารที่นำมาใช้

1. [Dense Passage Retrieval — Karpukhin และคณะ, EMNLP 2020](https://aclanthology.org/2020.emnlp-main.550/) ศึกษาการค้นข้อความด้วยตัวแทนความหมายของคำถามและข้อความเอกสาร เป็นพื้นฐานให้ใช้ embeddings ร่วมกับการค้นคำ แต่ผลทดลองในบทความไม่ใช่ผลวัดความแม่นยำของหนังสือไทยชุดนี้
2. [Gemini API: Embeddings](https://ai.google.dev/gemini-api/docs/embeddings) อธิบายการใช้ embeddings สำหรับ semantic search และการกำหนดงานค้นคืน สำหรับ `gemini-embedding-001` โครงการใช้ RETRIEVAL_DOCUMENT ตอนสร้างดัชนี และ RETRIEVAL_QUERY ตอนถาม คงโมเดลเดิมและใช้เวกเตอร์ 768 มิติ ปรับความยาวเป็นหนึ่งก่อนคำนวณ cosine
3. [ALCE — Enabling Large Language Models to Generate Text with Citations, EMNLP 2023](https://aclanthology.org/2023.emnlp-main.398/) ศึกษาคำตอบพร้อมการอ้างอิงและการประเมินคุณภาพการอ้างอิง การมี citation อย่างเดียวไม่ใช่หลักประกันว่าคำตอบครบหรือถูก โครงการจึงดึงคำตอบตรงจากข้อความที่สแกนและตรวจช่วงตัวอักษรกับต้นฉบับ ไม่ให้โมเดลแต่งข้อเท็จจริง
4. [PDF.js: Examples — Mozilla](https://mozilla.github.io/pdf.js/examples/index.html) รองรับการเปิดข้อมูล PDF การดึงแต่ละหน้า การวาดลง canvas และการปรับ viewport ตามขนาดและการหมุน โครงการส่งเฉพาะหน้าที่ใช้อ้างอิง แล้ววาดไฮไลต์ตามพิกัดบรรทัด ช่วยลดข้อมูลที่ส่งเมื่อเทียบกับส่ง PDF ทั้งเล่มทุกครั้ง

## คำศัพท์ 1,000–2,000 คำช่วยอะไร

การรวบรวมคำเรียก วิธีสะกดผิด ภาษาพูด และตัวอย่างคำถามช่วยให้ระบบจับหัวข้อและเจตนาได้ชัดขึ้น แต่จำนวนคำไม่ได้ทำให้ระบบเข้าใจความหมายหรือรับประกันความถูกต้องโดยตัวมันเอง ข้อเสนอของโครงการคือใช้คำศัพท์เป็นชั้นเสริม แล้วใช้ embeddings ค้นข้อความจริง พร้อมตรวจหลักฐานก่อนแสดงคำตอบ

โครงการมีไฟล์คำเรียกไทย อังกฤษ และคาราโอเกะ กับตัวอย่างคำถาม 1,500 ประโยคที่จัดหัวข้อและเจตนาไว้ ข้อความเหล่านี้เป็นร่างที่ระบบเขียนให้มีลักษณะภาษาพูด ไม่ใช่ข้อมูลที่เก็บจากผู้ใช้จริง ไม่อ้างว่าเขียนโดยมนุษย์ และไม่ใช่ผลการฝึกโมเดล ตัวอย่างไม่มีคำตอบ จึงใช้แทนหลักฐานจากหนังสือไม่ได้

ไฟล์ตัวอย่างรองรับการจับประโยคที่ตรงรายการ ส่วนคำถามที่ไม่ตรงรายการใช้ aliases, การค้นข้อความ และ dense retrieval การเพิ่มรายการต้องตรวจซ้ำด้วยชุดคำถามแยก ไม่ควรใช้ชุดตัวอย่างเดียวกับชุดประเมินแล้วรายงานว่าแม่นยำขึ้น

## สถาปัตยกรรมที่เลือก

- PDF ไทยฉบับ Now และ PDF อังกฤษเป็นแหล่งข้อมูลปัจจุบันทั้งคู่ แต่มีดัชนี พิกัด และรูป WebP แยกตามไฟล์และ hash
- เลือกภาษาหลักฐานก่อนค้น หากฉบับแรกตอบไม่ได้จึงตรวจอีกฉบับ ระบุภาษาของหลักฐานที่แสดงทุกครั้ง ไม่มีการอ้างว่าหน้าเดียวกันของสองเล่มมีตำแหน่งเหมือนกัน
- คง `gemini-3.5-flash-lite` ตามการตั้งค่าเดิม ใช้ช่วยตีความเส้นทางคำถามเมื่อจำเป็น ไม่รับข้อความคำตอบที่โมเดลสร้างเป็นข้อเท็จจริง
- คุยทักทาย ขอบคุณ และให้กำลังใจในการเรียนได้อย่างจำกัด คำถามเนื้อหาต้องผ่านการค้นหนังสือ ส่วนคำถามนอกเรื่องหรือหลักฐานไม่พอจะปฏิเสธ
- สอนทีละส่วนโดยแบ่งข้อความตามรอบหรือหัวข้อที่มีอยู่จริง แสดงสะสมเมื่อกดขั้นถัดไป พร้อมเลขหน้า เลขบรรทัด และไฮไลต์ของส่วนที่เลือก
- เก็บไฟล์โค้ด PDF metadata รูป และดัชนีไว้ใน repository ใช้ GitHub เป็นที่เก็บและแจกจ่ายไฟล์ ไม่เรียก GitHub เป็นฐานข้อมูลผู้ใช้
- ไม่มีฐานข้อมูลและไม่มีการเขียนบทสนทนาลงดิสก์ สถานะสนทนาอยู่ในหน่วยความจำของ Streamlit session ชั่วคราว เมื่อเปิด AI คำถามจะถูกส่งไปยังบริการ Gemini เพื่อประมวลผล จึงไม่ควรอ้างว่าเป็นระบบประมวลผลออฟไลน์ทั้งหมด

## ข้อจำกัดการประเมิน

การตรวจช่วงข้อความและพิกัดช่วยพิสูจน์ที่มาของคำตอบ แต่ไม่ได้พิสูจน์ว่าระบบเลือกข้อความที่ตอบตรงที่สุดทุกครั้ง ต้องวัด Recall@k, MRR, ความตรงของภาพ และความครบถ้วนของคำตอบกับชุดทดสอบที่มนุษย์ตรวจแยกต่างหาก รายงานการทดสอบโปรแกรมและการลองถามจริงเป็นหลักฐานการทำงาน ไม่ใช่ผลทดลองทางการศึกษาหรือการรับประกันความแม่นยำ 100%
