## การเลือกหลักฐานทั่วไปด้วย LLM — ปรับล่าสุด

เพิ่ม `services/evidence_selection.py` เป็นตัวเลือกหลักฐานร่วมทุกหัวข้อ ไม่ใช่กฎคำตอบเฉพาะ Bubble Sort คำถามธรรมชาติใช้ keyword/vector candidate pool แล้วให้โมเดลเดิมเลือก IDs/บรรทัดตามเจตนา ก่อนนำข้อความจริงไปแปล Candidate pool ไม่เกิน 48 ช่วง/18,000 อักขระข้อความต้นฉบับ ไม่ส่งทั้งเล่มทุกครั้ง คำถามหัวข้อเฉพาะที่ตรง เช่น Efficiency/ประสิทธิภาพ และคำขออ่านทั้งบทไม่ผ่านการตัดเลือกของ LLM

ตรวจ ID/ช่วงบรรทัด/ลำดับ/ซ้ำ/ต้นฉบับ และไม่ยอมรับข้อความคำตอบใหม่จาก selector โค้ดต้องคงครบ block; หาก API/JSON ไม่ผ่านใช้ fallback พร้อมแจ้ง หากโมเดลเลือกว่างจะตอบหลักฐานไม่พอ โหมด fallback เดิมเมื่อปิด AI ยังอยู่ กฎนิยามเฉพาะที่เคยแก้เป็นส่วนสำรอง ไม่ใช่กลไกหลักเมื่อเปิด AI

ทดสอบ API จริงทั้ง 5 sorts และตรวจ source texts ที่เลือก พบข้อจำกัดรอบแรกเรื่องโจทย์/โค้ดเกินเจตนา จึงเพิ่ม scope/body matching/ตัวกรองโจทย์และห้ามเลือก code สำหรับนิยามพื้นฐาน ทดสอบหน้าจอ Selection Sort ล่าสุดเลือกหน้า 46 บรรทัด 5–7 ไม่แสดง code ที่ไม่ขอ ผล full suite 86 tests ผ่าน พร้อม targeted selector 6 tests ผ่านหลังปรับตัวกรอง ไม่มีข้ออ้างว่า LLM เลือกถูกทุกคำถามหรือแปลถูก 100%

ตรวจหลังแก้ล่าสุด: selector/translation/AppTest รวม 13 tests ผ่าน; หน้าจอจริง Selection Sort เลือกคำอธิบายหน้า 46 บรรทัด 5–7 แปลไทยสำเร็จ หลักฐานภาพ `tmp/english_rebuild/generic-selector-proof.png`

## แก้คำพิมพ์ผิดและการเปิดทั้งบทโดยไม่ตั้งใจ

Root cause: `plan_query` รู้จำ typo แต่ downstream ใช้คำถามเดิม ทำให้ `selecion sort` ค้นไม่พบ ส่วน `selection sort` เมื่อไม่ใช้/ใช้ selector ไม่ได้ จะไป fallback exact chapter เพราะ regex นิยามเดิมไม่รองรับคำว่า divides จึงได้แบบฝึกหัดหน้า 45 และทั้งบท

แก้ให้ normalization ส่งต่อถึง search/selector/app จริง โดยเก็บคำถามที่ผู้ใช้พิมพ์ไว้แสดงตามเดิม รองรับ typo ใกล้เคียงชื่อทั้ง 5 algorithms และป้องกันการแก้คำอังกฤษจริง เช่น section เป็น selection นอกบริบทชื่อ sort ชื่ออัลกอริทึมเปล่าและคำขอนิยามเลือกคำอธิบายพื้นฐานทุกหัวข้อ ไม่เปิดทั้งบท; ยังเปิดทั้งบทได้เมื่อขอชัดเจน

Selector สำหรับนิยามไม่ส่ง proofs/invariants/code/costs ให้เลือกเกินเจตนา แต่การถามความซับซ้อนยังค้นส่วนนั้นได้ เมื่อ selector/API ไม่พร้อม ใช้พื้นฐานจากต้นฉบับเฉพาะคำถามที่มีนิยามรองรับ ถ้าไม่มีทางสำรองที่ตรง ให้บอกว่าบริการเลือกหลักฐานไม่พร้อม ไม่อ้างว่าหนังสือไม่มีข้อมูลและไม่เท keyword results ที่ไม่เกี่ยวข้อง

ทดสอบ API จริงทั้ง `selecion sort` และ `selection sort` พบ source Selection Sort และ state selected ดู `tmp/english_rebuild/selection-spelling-live-v2.json` API เลือกจำนวนช่วงต่างกันได้ แต่ไม่มี whole-chapter fallback/โจทย์หน้า 45 ในผลล่าสุด ทดสอบปิด AI และบังคับ API 429 แล้วคำถามทั้งคู่ยังใช้พื้นฐานหน้า 46 ได้

ผลตรวจรอบสุดท้ายของการแก้ typo/fallback: full suite 98 tests ผ่าน; ปรับ prose rendering เพิ่มแล้วตรวจ formatting/UI 15 tests ผ่าน ป้องกันข้อความอธิบายที่มี m=i หรือ For example ถูกแสดงเป็นโค้ดทั้งย่อหน้า (โค้ดจริงยังใช้กรอบจาก metadata) ตรวจเบราว์เซอร์จริงทั้งสองคำสำเร็จ ไม่ขึ้น 20 ส่วน ภาพ `tmp/english_rebuild/selection-typo-fixed-proof.png`
